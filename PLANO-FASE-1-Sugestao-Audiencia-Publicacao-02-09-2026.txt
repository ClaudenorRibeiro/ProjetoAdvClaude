2) PECA 1 - O PARSER (arquivo novo, front, funcao pura)
--------------------------------------------------------------------------------

ARQUIVO NOVO: frontend/src/utils/sugestoesPublicacao.js

  - Exporta: analisarPublicacao(texto, { dataPublicacao }) -> [ sugestao ]
  - Funcao PURA: sem estado, sem API, sem banco. Deterministica.
  - Formato de cada sugestao:
        {
          tipo: 'compromisso',
          subtipo: 'audiencia',
          titulo, data, hora, local, descricao,
          trechoOrigem, regra, confianca
        }

  REGRAS DA FASE 1 (familia "audiencia designada"), aprox. 6 a 10 padroes:
    - Gatilho: a palavra "audiencia" perto de
      (designo | designada | designe-se | aprazada | marcada | redesignada).
    - NEGATIVAS que CANCELAM a sugestao:
      "audiencia ... realizada | cancelada | prejudicada | adiada sine die".
    - DATA: padrao DD/MM/AAAA mais proxima do gatilho.
      Se vier sem ano ("dia 08/10"), usa o ano de dataPublicacao
      -> confianca MEDIA.
    - HORA: aceita "10:00 horas", "10h", "10:00min", "as 10 e 30".
    - LOCAL: trecho a partir de "na sala de audiencias" / "na " ate o fim
      da frase, incluindo o CEP quando presente.
    - MODALIDADE: PRESENCIAL | TELEPRESENCIAL | videoconferencia | semipresencial.
    - TIPO DE AUDIENCIA: UNA | conciliacao | instrucao | inicial.
    - CONFIANCA:
        ALTA  = data + hora + gatilho juntos.
        MEDIA = ano inferido, ou sem hora.
        (BAIXA nao ocorre nesta fase.)
    - Monta:
        titulo    = "Audiencia {tipo} - {numero_processo}"
        descricao = modalidade + local +
                    "Origem: publicacao no {numero_publicacao} de {data}"
    - Se nada casar -> retorna [].

  POR QUE NO FRONT E NAO NO BACK:
    A leitura ja tem o texto inteiro (nao chama obter). Rodar no front =
    zero mudanca de contrato de API, zero risco na query da listagem,
    100% removivel. Migrar para o back depois (badge na lista / cron) e
    trivial - mesma funcao pura.

3) PECA 2 - PAINEL "SUGESTAO" NA LEITURA (componente compartilhado)
--------------------------------------------------------------------------------

COMPONENTE NOVO, dentro do proprio Publicacoes.js
(ao lado de BarraAcoesPublicacao, que ja e compartilhado pelas abas AASP/CNJ):

    <PainelSugestoes
        pub={textoAberto}
        onUsar={(sug) => setAcaoAberta({ tipo:'compromisso', pub: textoAberto, sugestao: sug })}
    />

  - const sugestoes = useMemo(
        () => analisarPublicacao(pub.texto, { dataPublicacao: pub.data_publicacao }),
        [pub]
    );
  - Renderiza ACIMA da BarraAcoesPublicacao, nas DUAS telas
    (1 componente, chamado 2x).
  - Se sugestoes.length === 0: linha discreta
    "Nenhuma sugestao automatica - use os botoes abaixo." (sem poluicao).
  - Para cada sugestao, um cartao com:
      * selo de confianca (Alta / Conferir),
      * a frase-resumo ("Audiencia identificada para 08/10/2026 as 10:00"),
      * o TRECHO DE ORIGEM destacado (reusa o realcarTexto que ja existe),
      * botao [ Agendar audiencia - 08/10/2026 10:00 ].
  - So aparece se o usuario puder agir (podeAlterar || textoAberto.pode_agir)
    - mesma regra da BarraAcoesPublicacao.

4) PECA 3 - PRE-PREENCHER O "CRIAR COMPROMISSO"
           (via ponte; ZERO mudanca no ModalCompromisso)
--------------------------------------------------------------------------------

O ModalCompromisso (em Agenda.js) JA monta o formulario a partir de um objeto
"compromisso" quando ele NAO tem id:
    editando = !!(compromisso && compromisso.id)  -> fica false
    -> cria NOVO, mas com os campos ja preenchidos.

SO MUDA O INTERMEDIARIO ModalAcaoDaPublicacao (em Publicacoes.js):
    - hoje:  acaoAberta = { tipo, pub }
    - passa a: acaoAberta = { tipo, pub, sugestao }
    - na renderizacao do compromisso:

        <ModalCompromisso
           compromisso={sugestao ? {
             titulo: sugestao.titulo,
             descricao: sugestao.descricao,
             data: sugestao.data,
             hora_inicio: sugestao.hora || ''
           } : undefined}
           usuarios={usuariosAgenda} usuarioLogadoId={...} ehAdmin={...}
           publicacaoId={pub.id} onFechar={onFechar} />

    - Sem id -> salva como NOVO compromisso, com publicacao_id (vinculo ja
      existente), delegado para o proprio usuario (fallback ja existente).
    - O LOCAL entra na DESCRICAO (o ModalCompromisso nao tem campo "local";
      nao vou inventar um).

Os botoes manuais da BarraAcoesPublicacao continuam identicos
(passam sugestao: undefined).

--------------------------------------------------------------------------------
7) RISCOS E MITIGACAO
--------------------------------------------------------------------------------

  1. Falso positivo (data errada / audiencia que ja aconteceu).
     -> Nunca cria sozinho; sempre mostra o trecho de origem; regras
        negativas (realizada|cancelada) suprimem a sugestao; selo "Conferir"
        quando a confianca e media.
  2. Duas datas no texto (despacho x audiencia).
     -> Escolhe a data mais proxima do gatilho (designe-se / para o dia),
        nao a primeira do texto.
  3. Regra de regex lenta / travando (ReDoS).
     -> Padroes simples e ancorados, sem aninhamento perigoso; roda uma vez
        por abertura, sobre um texto de poucos KB.
  4. Texto sem padrao reconhecivel.
     -> Painel mostra "nenhuma sugestao automatica"; os botoes manuais
        continuam la. Nada quebra.
  5. Duplicar compromisso.
     -> Aviso via historico antes de abrir o modal.
