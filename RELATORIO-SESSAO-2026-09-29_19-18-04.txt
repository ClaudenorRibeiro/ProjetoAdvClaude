1.2 AVISO "JÁ EXISTE PERÍCIA AGENDADA DO MESMO TIPO"  (commit c9dcef2)
  Pedido: o sistema deveria avisar que já existia perícia técnica agendada
  e perguntar se era remarcação (print 2).
  Regra escolhida pelo usuário: olhar só o MESMO PROCESSO e o MESMO TIPO.
  Feito:
   - Ao salvar perícia nova, se já houver uma AGENDADA do mesmo tipo no
     mesmo processo, o sistema pergunta se é remarcação:
       * "Sim, é remarcação": pede o motivo; a antiga vira "Remarcada" e a
         nova é criada, na MESMA transação (tudo ou nada); reaproveita o
         aviso ao cliente de remarcação e atualiza a agenda do Google.
       * "Não, é outra perícia": salva como perícia adicional.
       * Se houver mais de uma agendada, o usuário escolhe qual remarca.
   - A checagem fica no SERVIDOR (não depende só da tela). O servidor recusa
     remarcar perícia de outro processo, que não esteja agendada, sem motivo
     ou sem permissão de alterar perícias.
   - Vale só para cadastro novo (não para editar perícia existente).
   - Sem alteração de banco.

 4) SQL PARA O BANCO (obrigatório antes de subir o código novo)
-----------------------------------------------------------------------
  Arquivo local desta sessão: scripts/2026-09-29_status_encerra_processo.sql
  (NÃO vai ao Git). O usuário já rodou no banco LOCAL (o print do HeidiSQL
  mostrou a conferência; o log indicou "Registros afetados: 1" e
  "Avisos: 1" — o aviso não foi identificado). Falta rodar na AWS.

  ORDEM CORRETA: rodar o SQL ANTES de subir o código. Sem a coluna, o
  Dashboard e o cadastro de status dão erro. Com o código antigo na AWS o
  SQL é inofensivo (só acrescenta coluna com padrão 0).

  Conteúdo do script (seguro para rodar mais de uma vez):

  -- 1) Verificação prévia (só leitura)
  SELECT COUNT(*) AS coluna_ja_existe
    FROM information_schema.COLUMNS
   WHERE TABLE_SCHEMA = DATABASE()
     AND TABLE_NAME   = 'tblstatusproc'
     AND COLUMN_NAME  = 'encerra_processo';

  -- 2) Cria a coluna (só se ainda não existir)
  SET @tem := (SELECT COUNT(*) FROM information_schema.COLUMNS
                WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'tblstatusproc' AND COLUMN_NAME = 'encerra_processo');
  SET @sql_coluna := IF(@tem = 0,
    'ALTER TABLE tblstatusproc ADD COLUMN encerra_processo TINYINT(1) NOT NULL DEFAULT 0 COMMENT ''1 = processo com este status está encerrado (ex.: Arquivado) e fica fora das estatísticas de processos parados'' AFTER nome',
    'SELECT ''coluna encerra_processo ja existe - nada a fazer'' AS aviso');
  PREPARE stmt FROM @sql_coluna;
  EXECUTE stmt;
  DEALLOCATE PREPARE stmt;

  -- 3) Marca os status chamados "Arquivado" que já existem (só na 1ª vez)
  SET @sql_marca := IF(@tem = 0,
    'UPDATE tblstatusproc SET encerra_processo = 1 WHERE nome = ''Arquivado'' AND ativo = 1',
    'SELECT ''marcacao inicial ja feita antes - nada a fazer'' AS aviso');
  PREPARE stmt FROM @sql_marca;
  EXECUTE stmt;
  DEALLOCATE PREPARE stmt;

  -- 4) Conferência (só leitura)
  SELECT id, nome, encerra_processo, ativo FROM tblstatusproc ORDER BY nome;

  Consulta de conferência dos status (só leitura), útil na AWS ANTES:
  SELECT sp.id, sp.nome, COUNT(pr.id) AS processos_ativos
    FROM tblstatusproc sp
    LEFT JOIN tblproc pr ON pr.status_id = sp.id AND pr.ativo = 1
   WHERE sp.ativo = 1
   GROUP BY sp.id, sp.nome
   ORDER BY sp.nome;

  No LOCAL, essa consulta mostrou: "Arquivado" com 4.660 processos ativos e
  "Conhecimento" com 1.569; os demais status com 0 ou 1. O script marca
  SÓ o nome exato "Arquivado". Outros status que devam encerrar o processo
  precisam ser marcados na tela (botão "…" do Status > Editar).
