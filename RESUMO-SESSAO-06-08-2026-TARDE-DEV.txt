1) RETROATIVIDADE DA AUDIÊNCIA PASSOU A RESPEITAR O HORÁRIO  (só front; SEM SQL)
------------------------------------------------------------------------
Problema: o aviso "Data retroativa" (na tela de nova/editar audiência) só
olhava a DATA. Então, se agora são 13:37, dava para agendar audiência para
HOJE às 08:00 sem nenhum aviso. Além disso, o "hoje" era calculado no fuso
errado (UTC), não no de Brasília.

O que mudou:
- Agora o sistema considera DATA + HORA (no fuso de Brasília):
  * Dia anterior a hoje  -> aviso "Data retroativa: dd/mm/aaaa" (como antes).
  * Hoje, mas com horário já passado -> NOVO aviso
    "Horário já passou: dd/mm/aaaa às HH:MM".
  * Data/hora no futuro -> sem aviso.
- Continua sendo um AVISO ("Confirmar mesmo assim"), não um bloqueio, porque
  às vezes se registra uma audiência que já aconteceu.
- Vale nos dois lugares: criar audiência e editar audiência.
- Não mexeu em Agenda nem Tarefas (a trava de data delas é outra coisa).

3) "REGISTRAR ATA": NOVA SEÇÃO "O QUE TEVE NESSA AUDIÊNCIA?" (ESQUELETO)
   (front + back; COM SQL)
------------------------------------------------------------------------
Uma ata pode ter várias coisas. Criamos a base de uma seção com 7 opções
(checkboxes): Prazo, Perícia, Acordo, Nova audiência, Alvará,
Desistência da Ação, Retornem aos autos.

Como funciona:
- Ao MARCAR um checkbox, aparece o recurso daquela opção (que fica oculto
  até marcar). Assim a tela não fica poluída.
- "Acordo" e "Nova audiência": são os botões que JÁ existiam e funcionam;
  agora só aparecem quando você marca o checkbox correspondente.
- "Prazo", "Perícia", "Alvará", "Desistência da Ação" e "Retornem aos autos":
  por enquanto mostram uma faixa "recurso em implementação, será liberado em
  breve". O checkbox já marca e JÁ FICA GRAVADO na ata; a AÇÃO de cada um
  será construída DEPOIS, UMA DE CADA VEZ (foi a abordagem combinada).
- Fica gravado no banco QUAIS opções foram marcadas em cada ata.

IMPORTANTE (a fazer no futuro, um por vez):
- Prazo: o backend já aceita criar prazos junto da ata (é o próximo natural).
- Perícia: precisa do perito e pode ser mais de uma perícia.
- Alvará / Desistência da Ação / Retornem aos autos: AINDA VAMOS DEFINIR o
  que cada botão faz (ex.: alvará vira lançamento no Financeiro? tarefa?
  andamento? desistência muda o status do processo? etc.). Nada decidido.


4) CAMPO "ADVOGADO(A) QUE ACOMPANHOU A AUDIÊNCIA" NA ATA  (front + back; COM SQL)
------------------------------------------------------------------------
Dúvida do usuário: "advogado vai no cadastro de Pessoas (por causa da OAB)
ou em outro lugar?"

Decisão (boas práticas): advogado NÃO vai em Pessoas. Pessoas é para as
PARTES/CLIENTES (autor, réu, perito, testemunha). O sistema já tem o lugar
certo para advogado, e já com OAB:
  - Advogados do próprio escritório (que logam) = tabela de usuários.
  - Advogados externos/correspondentes = tabela de "freelas" (já com OAB e
    já com um botão "(…)" para cadastrar).

O que foi feito:
- No TOPO da janela "Registrar Ata", campo "Advogado(a) que acompanhou a
  audiência:" — uma lista mostrando Nome — OAB (ex.: "Antônio — SP222418").
- Opção "Ninguém (a parte compareceu sozinha)" — para o caso do advogado ter
  atrasado e a parte entrar sozinha. É diferente de "não informado".
- Já vem PRÉ-PREENCHIDO com o advogado responsável da audiência (dá para
  trocar).
- Botão "(…)" cadastra um advogado novo na hora (com OAB) e já o seleciona.
- É OBRIGATÓRIO informar? Isso agora é uma PREFERÊNCIA DE CADA ESCRITÓRIO:
  em Configurações do Escritório há o interruptor "Exigir advogado
  acompanhante ao registrar a ata". Se ligado e o campo ficar vazio, aparece
  um aviso amigável dentro da própria janela.

Observação honesta: por enquanto isso GRAVA o advogado na ata. EXIBIR esse
advogado de volta numa tela de "ver ata" é um passo separado (hoje não existe
uma tela de "ver ata" pronta). Fica anotado como pendência, se você quiser.


SQL RODADO NESTA SESSÃO (LOCAL + as 2 AWS)
========================================================================
-- ata_audiencia: 5 flags dos checkboxes + advogado acompanhante (3 colunas + 2 FKs)
ALTER TABLE `ata_audiencia`
  ADD COLUMN `teve_prazo`         tinyint DEFAULT 0 AFTER `nova_audiencia`,
  ADD COLUMN `teve_pericia`       tinyint DEFAULT 0 AFTER `teve_prazo`,
  ADD COLUMN `teve_alvara`        tinyint DEFAULT 0 AFTER `teve_pericia`,
  ADD COLUMN `teve_desistencia`   tinyint DEFAULT 0 AFTER `teve_alvara`,
  ADD COLUMN `teve_retorno_autos` tinyint DEFAULT 0 AFTER `teve_desistencia`,
  ADD COLUMN `advogado_id`        int DEFAULT NULL,
  ADD COLUMN `advogado_freela_id` int DEFAULT NULL,
  ADD COLUMN `sem_advogado`       tinyint DEFAULT 0,
  ADD CONSTRAINT `fk_ata_advogado`        FOREIGN KEY (`advogado_id`)        REFERENCES `usuarios` (`id`)          ON DELETE SET NULL,
  ADD CONSTRAINT `fk_ata_advogado_freela` FOREIGN KEY (`advogado_freela_id`) REFERENCES `advogados_freela` (`id`) ON DELETE SET NULL;

-- configuracoes_escritorio: preferência "exigir advogado na ata"
ALTER TABLE `configuracoes_escritorio`
  ADD COLUMN `ata_advogado_obrigatorio` tinyint DEFAULT 0;

Segurança das exclusões: as 2 chaves estrangeiras do advogado são
ON DELETE SET NULL — se um advogado for excluído, o vínculo na ata só é
zerado (não deixa ata órfã). A ata continua sendo "tabela folha".
